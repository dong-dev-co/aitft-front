AI Company Tycoon은 여러 AI 모델을 하나의 가상 회사에 배치하는 개인용 업무 운영 도구입니다. 직원을 채용하듯 역할과 권한을 정하고, 업무 하나를 통째로 맡기거나 최대 10단계 파이프라인으로 직접 설계해 지시한 뒤 결과를 검토하세요. 실행 타임라인·토큰 사용량·문서와 이미지 산출물까지, 타이쿤처럼 친근한 화면 아래에는 결과물과 승인 이력을 남기는 신뢰성 있는 시스템이 있습니다.

Features

타이쿤 화면, 실제로는 업무 시스템

표면은 친근한 경영 게임이지만, 그 아래에는 담당자·완료 조건·비용·승인 이력을 남기는 절차가 있습니다.

👤

AI 직원 채용

Anthropic·OpenAI·Google 기본 제공, NVIDIA NIM·Hugging Face·로컬 런타임 등 OpenAI 호환 주소는 무엇이든 연결로 추가해 직원에게 배정할 수 있습니다. 직원마다 최대 응답 길이도 정합니다.

🟢

살아 있는 오피스

직원이 지금 무엇을 하는지 실제 상태로 보여줍니다. 작업 중·앞 단계 대기·막힘·검토 대기, 할 일이 없으면 저마다 다른 모습으로 쉬고 있습니다.

🗂️

업무 보드

할 일 · 진행 중 · 검토 · 완료로 이어지는 칸반 보드. 실행하면 바로 진행 중으로 옮겨지고, 업무 수정은 할 일에서만 됩니다. 칼럼의 이름·색·순서를 바꾸고 상태를 직접 추가할 수 있습니다.

🧩

티켓 오케스트레이션

직원 한 명이 처음부터 끝까지 맡거나, 기획·개발·문서·번역처럼 단계를 직접 짜는 파이프라인(최대 10단계)으로 여러 직원이 이어받게 할 수 있습니다.

📝

단계마다 남는 문서

기획 단계는 기획서를, 작업 단계는 결과 문서를 남깁니다. 개발 단계라면 사용한 언어·구조·실행 방법·핵심 코드 설명이 코드와 함께 나옵니다.

✅

직원별 검토 · 실행 타임라인

초안은 직원별로 묶여 있어, 이름을 누르면 그 직원의 결과물이 앱 안의 보기 창에서 바로 열립니다. 누가 어느 단계를 얼마나 걸렸는지도 막대로 보입니다.

🎨

이미지 생성

이미지 연결을 배정한 직원은 글 대신 이미지 파일을 만듭니다. 만들어진 이미지도 초안으로 먼저 쌓이고, 검토 화면에서 확인 후 승인해야 저장됩니다.

📁

작업 폴더 안에서만

AI 직원은 업무마다 하나의 작업 폴더 안에서만 파일을 다룹니다. 경로 이탈은 코드 수준에서 차단됩니다.

📋

팀 규칙 문서

팀 규칙은 폴더 안의 마크다운 파일입니다. git으로 관리하고, 직원별로 적용 범위를 지정할 수 있습니다.

📊

사용량 대시보드

기간별·직원별·모델별 토큰 사용량을 그래프로 보여줍니다. 기기마다 따로 기록되고 합쳐서 보여주므로 숫자가 서로 덮어써지지 않습니다.

🔌

MCP 도구 연동

저장소 읽기·이슈 생성처럼 외부 도구를 MCP 서버로 연결합니다. 체크한 도구만 자동 실행되고, 나머지는 호출마다 이름과 인자를 보여주고 승인을 받습니다.

🔄

기기 간 동기화

Google 계정으로 로그인하면 회사·직원·업무·결과물·실행 기록·팀 규칙·모델 연결까지 모두 다른 기기와 맞춰집니다. 앱을 열 때, 다시 볼 때, 5분마다. API 키만은 기기에 남습니다.

📎

파일 첨부

업무를 만들 때 참고 자료를 첨부하면 작업 폴더로 복사되어 직원이 함께 읽습니다. 작업 폴더 밖의 파일은 읽을 수 없으므로 참조가 아니라 복사됩니다.

🧠

업무 기억

반려하면 사유가 직원에게 전달되고, 다시 실행할 때 처음부터가 아니라 이어서 고칩니다. 기획부터 다시 할지, 기획은 두고 작업만 다시 할지도 고를 수 있습니다.

💾

원하는 형식으로 저장

파일 이름이 형식을 정합니다. docx·xlsx·pdf는 직원이 마크다운으로 쓰면 앱이 변환하고, API 키는 운영체제 암호화 저장소에만 보관됩니다.

Security

믿고 맡길 수 있는 구조

고비용 실행, 외부 전송, 파일 변경, 최종 확정에는 항상 사람의 확인 절차가 있습니다.

1

경로 봉쇄는 코드에서만

AI 직원은 배정된 작업 폴더를 벗어날 수 없습니다. realpath로 재확인하며, 경로 이탈 시도는 승인 대상이 아니라 즉시 차단됩니다.

2

승인은 OS 기본 대화상자

파일 쓰기·삭제 승인 창은 운영체제 기본 대화상자로 표시됩니다. 모델이 만든 화면으로는 흉내낼 수 없고, 기본 선택은 항상 거부입니다.

3

팀 규칙은 AI에게 읽기 전용

AI 직원은 자신에게 적용되는 팀 규칙 파일을 읽을 수 있지만 고칠 수 없습니다. 자기 지시를 스스로 바꿀 수 없도록 막습니다.

4

API 키·세션은 OS 암호화 저장소

API 키와 로그인 세션은 평문으로 저장되지 않으며, 화면(렌더러)에는 토큰이 전달되지 않습니다.

5

모델 출력은 신뢰하지 않는 입력

AI가 만든 결과물, 문서·MCP의 지시는 참고 정보로만 취급되며 시스템 규칙이나 승인 절차를 우회할 수 없습니다.

Installation

설치 방법

아직 Apple 공증을 거치지 않은 빌드입니다. 처음 실행할 때 한 번 허용 절차가 필요합니다.

설치 파일 다운로드

위 다운로드 버튼으로 원하는 운영체제용 파일을 받습니다. macOS(Apple Silicon·Intel), Windows(.exe), Linux(x86_64 .deb·.AppImage)를 지원합니다.

Applications 폴더로 이동

dmg를 열고 AI Company Tycoon 아이콘을 Applications 폴더로 드래그합니다.

첫 실행 허용

처음 열면 "Apple이 확인할 수 없습니다" 경고가 뜹니다. 한 번 열기를 시도한 뒤 시스템 설정 → 개인정보 보호 및 보안에서 그래도 열기를 누르세요. 이후로는 그냥 열립니다. Windows에서는 SmartScreen이 뜨면 추가 정보 → 실행을 누르세요.

⚠️ 이전 버전에서 "손상되었기 때문에 열 수 없습니다"가 떴다면 새 버전을 받거나, 터미널에서 xattr -cr /Applications/AI\ Company\ Tycoon.app 실행 후 다시 여세요.

API 키 연결

연결 설정에서 사용할 모델 제공자(Anthropic, OpenAI, Google, NVIDIA NIM, Hugging Face)의 API 키를 입력합니다. 키는 OS 암호화 저장소에 보관됩니다.

AI 직원 채용 후 시작

직원 관리에서 역할에 맞는 AI 직원을 채용하고, 업무 보드에서 업무를 만들어 배정하면 바로 시작할 수 있습니다.

FAQ

자주 묻는 질문

로그인해야 쓸 수 있나요?

아니요. 로그인은 선택 사항입니다. 로그인하지 않아도 모든 핵심 기능이 로컬에서 그대로 동작합니다. Google 계정으로 로그인하면 기기 간 동기화가 켜집니다.

로그인하면 동기화를 끌 수 있나요?

로그인 자체는 선택이지만, 일단 로그인한 뒤에는 동기화가 자동으로 켜지며 이를 개별적으로 끄는 옵션은 없습니다. 동기화 없이 로그인만 하고 싶다면 로그아웃 상태(로컬 모드)로 사용하세요.

무엇이 다른 기기로 동기화되나요?

회사·내 프로필, 직원 설정, 업무와 보드, 결과 텍스트·기획 스펙·반려 사유, 실행 기록과 타임라인, 첨부와 승인한 결과물 파일, 토큰 사용량, 모델 연결(주소·모델), 팀 규칙 파일까지 모두입니다. API 키와 MCP 서버 설정, 승인 전 초안만 그 기기에 남습니다. 앱을 열 때, 창으로 돌아올 때, 5분마다, 그리고 무언가를 고친 직후에 맞춰집니다.

응답이 잘렸다는 오류가 나요.

직원의 최대 응답 길이에 걸린 것입니다. 직원 관리에서 그 직원을 열어 값을 늘리세요(256~128,000 토큰). 비워두면 Anthropic은 16,000, 그 밖의 연결은 서버 기본값을 씁니다. 업무를 더 작은 단위로 나누는 것도 방법입니다.

API 키는 어디에 저장되나요?

운영체제의 암호화 저장소(키체인)에만 저장됩니다. 데이터베이스나 화면 상태에 평문으로 남지 않으며, 기기 간 동기화 대상에도 포함되지 않습니다.

오프라인에서도 사용할 수 있나요?

네. 로컬 우선(local-first) 구조라 오프라인에서도 업무 생성·관리가 가능합니다. 다만 AI 직원의 실제 업무 실행에는 해당 모델 API 호출을 위한 네트워크 연결이 필요합니다.

Windows나 Intel Mac도 지원하나요?

네. macOS(Apple Silicon·Intel), Windows(.exe), Linux(x86_64 .deb·.AppImage) 빌드를 모두 제공합니다. macOS·Windows 빌드는 아직 Apple 공증·코드 서명 전이라 첫 실행 시 한 번 허용 절차가 필요합니다.

실행 취소나 파일 삭제가 안전한가요?

AI 직원의 파일 쓰기·생성은 실행당 1회, 삭제는 매번 OS 기본 승인 대화상자를 거칩니다. 기본 선택은 항상 거부이며, 작업 폴더 밖 경로 접근은 승인 여부와 무관하게 코드 수준에서 차단됩니다.

파이프라인은 어떻게 동작하나요?

업무를 만들 때 직원 한 명이 처음부터 끝까지 맡는 단일 담당 대신, 기획·개발·문서·번역 같은 단계를 최대 10개까지 직접 구성해 여러 직원이 순서대로 이어받게 할 수 있습니다. 모든 단계가 문서(기획서, 개발 단계라면 언어·구조·실행 방법·핵심 코드 설명)를 남기고, 산출물은 초안(.draft)에 먼저 쌓입니다. 검토 화면에서 직원별로 확인한 뒤 승인해야 실제 작업 폴더로 옮겨집니다.

MCP 서버를 연결하면 무엇이 위험해지나요?

MCP 도구는 작업 폴더 밖(저장소, 외부 서비스 등)에 닿는 것이 목적이라 파일 도구처럼 가둘 수 없습니다. 그래서 미리 체크해 둔 도구만 자동 실행되고, 나머지는 호출할 때마다 도구 이름과 보낼 값 전체를 보여주는 OS 대화상자로 승인을 받아야 합니다. 기본 선택은 항상 거부입니다.
